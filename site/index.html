Which functions do many independent apps keep rewriting by hand? A probe over Django and LLM apps on GitHub, compared against a control group of ordinary Python repos. Clusters are candidates for review, not proof of a missing library.

The hypothesis

If many unrelated owners rewrite the same functionality with different code, a library may be missing, or an existing one is not being found. This is a supply-side signal: nobody asked for the library, but the code shows the need.

Pipeline

    The control group

    The argparse problem

    In the 200-repo pilot, the first domain view ranked clusters by how much of their owners came from one domain (≥80 %). LLM apps were 65 % of all owners, so generic Python utilities — main() with argparse, logging setup, YAML config loading — looked "LLM-specific" just because most repos were LLM apps. Four of them were in the LLM top 20.

    Fix, in three steps: (1) enrichment against a base rate with Laplace smoothing and Benjamini-Hochberg q-values; (2) a control group of ordinary Python repos, so enrichment is measured as share of domain repos ÷ share of control repos; (3) clusters present in many control repos are flagged generic and listed apart. argparse, logging and YAML now sit in the generic section (they appear in 7–12 % of control repos).

    The final view keeps it simple: a cluster is domain-specific if it has ≥ owners in its domain and ≤ control repos. Enrichment and q are shown, not used as filters: with 300 control repos, a cluster needs ~30 LLM owners before any test can reach significance.

    Labeling

    The top clusters were labeled twice. Jev 1.13 (TypeSafe, via OpenRouter's System One endpoint) scored four propositions — SDK usage, framework idiom, reimplemented utility, other — and its category is the most probable one (marked ambiguous if it beats the runner-up by less than ). Claude Haiku answered the same question as JSON, with a one-line description and up to three PyPI libraries. A label is confirmed when both agree and Jev is not ambiguous.

    Each library Haiku proposed was checked against the PyPI JSON API and scored by Jev ("this library directly solves the need"); only libraries that exist and score ≥ are kept. "Already declared" is the share of the cluster's repos that list one of them in their declared dependencies.
